## 3. 统一范式（手感深化只读计数）

```js
let _fxShakes = 0, _fxBursts = 0;
// 触发点（计数器无条件递增，仅 Juice 调用受守卫）：
_fxShakes++; if (typeof Juice!=='undefined' && Juice.shake) Juice.shake(0.3);
_fxBursts++; if (typeof Juice!=='undefined' && Juice.burst) Juice.burst(x, y, {n:14});
// newGame/reset: _fxShakes = 0; _fxBursts = 0;
// window.__t: fxShakes: () => _fxShakes, fxBursts: () => _fxBursts
```

**要点**：
- 计数器递增**无条件**，只有 `Juice.*` 调用受 `typeof Juice!=='undefined'` 守卫——保证 harness 无 Juice 桩也能驱动测试。
- burst 坐标用**确定性表达式**（格子中心 `c*CELL+CELL/2`、`boss.x+boss.w/2` 等），绝不用 `Math.random`（全局随机流共享，会移位其他测试）。
- 因目标游戏都已有零星 Juice 调用但缺统一钩子，核心策略是**在既有 `Juice.shake/burst` 调用点旁挂计数器递增**（零新增视觉、零双触发），仅必要时补未覆盖过程时刻。
- **hanoi/hashi 补 shake**：初次注入时这两款原无 shake 调用、只加了 burst。手感深化应是 shake+burst 双反馈，已续派补 `Juice.shake(0.5)` 并追加断言。
- **fillomino 测试驱动修复**：原测试逐格填解但 `newPuzzle` 后 grid 全 0（线索格也为 0），含线索格区域填不完整导致触发条件不成立。改为找第一个空格填 `1` → 孤立单格区域 size=1=val=1 必触发。

## 5. 验收流程与踩坑

1. **grep 独立核对**：`grep -c '_fxShakes' <game>.html` + `grep -c 'fxShakes' <game>_test.js`，html≥3、test≥2 才算落地。
2. **亲跑单测**：`node <game>_test.js`，看 ✗ 数量 + **有无 ReferenceError/TypeError 堆栈**。
3. **全量回归**：`node games/tests/logic/run.js` 看汇总「X/X 通过 · 全绿」。

**⚠️ harness 不置 exit code**：`ok/eq` 失败只打 `✗`、不抛错、不置非零退出码。零输出 + exit 0 = 全部通过。但异常堆栈也可能让代理误报「✗=0 通过」——验收务必同时 grep 异常关键字。

**⚠️ fx 断言段前置 newGame**：若前面测试已驱动过触发点，段首必须先 newGame/setBoard 重置再断言「初始=0」，否则计数器已被前面的测试递增。

**⚠️ 子代理空跑/半途异常**：所有 "completed" 通知一律先 grep 独立核实再采信；空跑/半途用 `SendMessage` 续派（可重激活，附完整指令）。
