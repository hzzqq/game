## 2. 统一范式

### confetti 只读钩子（补全用）
```js
let _confettiFired = false;
// 胜利点：
if (!_confettiFired) {
  _confettiFired = true;                 // 无条件置位
  if (typeof Juice!=='undefined' && Juice.confetti) Juice.confetti();
}
// newGame/reset: _confettiFired = false;
// window.__t: confettiFired: () => _confettiFired
```

### 手感深化只读计数（深化用）
```js
let _fxShakes = 0, _fxBursts = 0;
// 触发点（计数器无条件递增，仅 Juice 调用受守卫）：
_fxShakes++; if (typeof Juice!=='undefined' && Juice.shake) Juice.shake(0.3);
_fxBursts++; if (typeof Juice!=='undefined' && Juice.burst) Juice.burst(x, y, {n:14});
// newGame/reset: _fxShakes = 0; _fxBursts = 0;
// window.__t: fxShakes: () => _fxShakes, fxBursts: () => _fxBursts
```

**要点**：
- 计数器/标志置位**无条件**，只有 `Juice.*` 调用本身受 `typeof Juice!=='undefined'` 守卫——保证 harness 无 Juice 桩也能驱动测试。
- burst 坐标用**确定性表达式**（格子中心 `c*CELL+CELL/2`、`boss.x+boss.w/2` 等），绝不用 `Math.random`（全局随机流共享，会移位其他测试）。
- 派发前 `grep 'Juice\.' <game>.html` 避开已有调用点，防双触发。本轮 gun(13)/fighting(9)/flappy(4)/icefire(4)/invaders(3)/golf(3)/go(1)/hex(1)/jungle(1)/kakurasu(1) 均有既有调用，只补未覆盖时刻。

## 4. 验收流程与踩坑

1. **grep 独立核对**：`grep -c '_fxShakes' <game>.html` + `grep -c 'fxShakes' <game>_test.js`，html≥3、test≥2 才算落地。
2. **删行检查防偷删**：`git diff --numstat` + `awk '$2>3'`（测试）/`awk '$2>10'`（HTML），输出空=纯追加。
3. **亲跑单测**：`node <game>_test.js`，看 ✗ 数量 + **有无 ReferenceError/TypeError 堆栈**。
4. **全量回归**：`node games/tests/logic/run.js` 看汇总「X/X 通过 · 全绿」。

**⚠️ harness 不置 exit code**：`ok/eq` 失败只打 `✗`、不抛错、不置非零退出码。零输出 + exit 0 = 全部通过。**但异常堆栈（如 `H.eq is not defined`）也可能让代理误报"✗=0 通过"**——本轮 gp-22 就在 jungle/kakurasu 用了未定义的 `H.eq/H.ok`（文件头是解构导入 `{ok,eq}`），跑到追加段直接 ReferenceError 崩溃，崩溃前无失败行故看似 ✗=0。已 sed 修复（`H.eq(`→`eq(`）。**验收务必同时 grep 异常关键字。**

**⚠️ 子代理空跑/半途异常率**：本批次 4 个初派代理中 2 个空跑（1-2 分钟返回拒答文本、一行未写）、1 个半途中断。对策：所有 "completed" 通知一律先 grep 独立核实再采信；空跑/半途用 `SendMessage` 续派（可重激活，附完整指令），本轮全部续派成功补齐。
